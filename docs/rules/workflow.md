# 워크플로우 규칙

## 계획 준수

- 모든 개발은 [개발 계획서](../plan/index.md)의 Phase 순서대로 진행한다.
- 계획에 없는 기능을 임의로 추가하지 않는다.
- 범위 변경이 필요한 경우, 계획서를 먼저 업데이트한 뒤 개발을 시작한다.

## 커밋 메세지 추천

- 작업이 완료되면 반드시 커밋 메세지를 추천한다.
- 형식은 `type(scope): 설명` 을 따른다.

| type | 사용 시점 |
|------|-----------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 개선 |
| `docs` | 문서 작성/수정 |
| `chore` | 빌드 설정, 패키지 관리 |
| `test` | 테스트 추가/수정 |

예시:
```
feat(auth): 직군 선택 회원가입 폼 추가
fix(sm2): 첫 학습 시 interval이 음수가 되는 버그 수정
docs(plan): phase-2 알고리즘 상세 계획 업데이트
```

## 타입 및 린트 체크

작업 완료 전 반드시 아래 두 명령을 실행하고 오류가 없음을 확인한다.

```bash
pnpm build      # TypeScript 빌드 체크 포함
pnpm lint       # ESLint 오류 체크
```

- 타입 오류(`any` 남용 포함)가 있으면 커밋하지 않는다.
- lint 경고도 무시하지 않고 해결한다.
